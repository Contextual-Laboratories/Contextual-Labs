# Support

**GitHub is where support happens for Contextual** — split across two
tools, on purpose:

- **[Issues](../../issues/new/choose)** — bug reports, docs feedback, and
  concrete feature requests. Pick the template that matches; each one
  routes into a small `type:`/`area:` label taxonomy so issues stay
  searchable and triage-able.
- **[Discussions](../../discussions)** — "how do I...?" questions, early
  feature ideas worth kicking around before they're a formal ask, and
  general chat. Start in **Q&A** for questions, **Ideas** for feature
  brainstorming. Keeping this separate from Issues is what keeps the bug
  tracker actually trackable.

**Typical first response: 1–3 business days.** That's an acknowledgment
and a label (or a reply, for Discussions), not necessarily a fix — this
is a solo-maintained project, so full resolution timelines vary with
severity and complexity. If it's been longer than that with no response,
a bump comment is always fair game.

Every new issue also gets an automatic welcome comment confirming it's
been received — if you don't see one within a few minutes of opening,
something's probably wrong on our end, not yours.

## Known issues

Before filing a new issue, [check `KNOWN-ISSUES.md`](KNOWN-ISSUES.md) — a
short, hand-maintained list of bugs already on our radar. It might save
you a duplicate report.

## Security vulnerabilities

Don't open a public issue for a security vulnerability. See
[`SECURITY.md`](SECURITY.md) for the private reporting channel.

## Everything else

For anything that isn't a bug, docs issue, or feature request —
`team@contextuallabs.dev`.
